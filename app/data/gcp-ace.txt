# 01 プロジェクト・IAM / リソース
Organization|企業所有のGoogle Cloudリソース階層の最上位で、組織ポリシーを適用する単位は？|組織の配下にフォルダやプロジェクトを構成する。
Folder|複数プロジェクトを部署や環境でグループ化し、IAM等を継承させたい。|フォルダは組織内の階層構造を作る。
Project|Google CloudでAPI有効化、IAM、リソースの利用をまとめる基本的な管理単位は？|プロジェクトには各種リソースが作成される。
Billing account|複数プロジェクトの使用料金を一括で支払うためリンクする単位は？|請求先アカウントをプロジェクトにリンクする。
# 01 プロジェクト・IAM / 認証
サービスアカウント|Compute EngineやCloud RunのアプリがGoogle Cloud APIへアクセスするためのワークロード用主体は？|人間でないワークロードのIDとしてIAMロールを付与できる。
カスタムロール|事前定義ロールに不要な権限が含まれるため、個別の許可を組み合わせて最小権限ロールを作りたい。|対応するIAM権限の集合を定義する。
Workload Identity Federation|AWSやオンプレミスのワークロードが長期サービスアカウントキーなしでGoogle Cloudへ認証したい。|外部IdPの認証を短期のGoogle Cloud認証情報と交換する。
Organization Policy|組織内で特定リージョン以外のリソース作成などを制約したい。|IAMのアクセス許可とは別にリソース構成の制約を適用する。
# 02 コンピューティング / 実行環境
Compute Engine|OSやカーネルを自分で管理する仮想マシンをGoogle Cloud上で起動したい。|IaaSのVMサービス。マシンタイプ、ディスク、ネットワークなどを設定する。
Cloud Run|HTTPコンテナをサーバー管理なしで稼働させ、リクエスト数に応じてゼロまでスケールさせたい。|マネージドコンテナ実行環境。サービスの最小インスタンス数等で挙動を設定する。
GKE|Kubernetes APIやマニフェストでコンテナを管理し、コントロールプレーンをマネージドにしたい。|Google Kubernetes Engineを利用する。
Cloud Run jobs|HTTPリクエストを待ち受けず、完了すると終了するコンテナのバッチ処理を実行したい。|ジョブは実行ごとにタスクを開始し終了まで実行する。
# 02 データ / ストレージ
Cloud Storage|画像やバックアップ等の非構造化データをオブジェクトとして保存したい。|バケットとオブジェクトを用いるオブジェクトストレージ。
Persistent Disk|Compute Engineの永続ブロックディスクを利用したい。|VMからブロックデバイスとして扱う。ゾーン・リージョン構成がある。
Filestore|複数Linux VMからNFSを用いて共有ファイルを利用したい。|マネージドNFSファイルサーバー。
BigQuery|大量の構造化データをサーバー管理なしでSQL分析したい。|分析向けデータウェアハウス。
# 02 データ / DB
Cloud SQL|既存PostgreSQLアプリを大きな変更なくマネージドRDBへ移したい。|PostgreSQL、MySQL、SQL ServerのマネージドDB。
Spanner|強い整合性を持つリレーショナルデータベースをグローバルに水平スケールさせたい。|分散SQLと強い整合性を提供する。
Firestore|モバイルアプリのドキュメント型データをサーバーレスDBで管理したい。|NoSQLドキュメントDB。リアルタイム更新にも対応する。
Bigtable|大量の時系列データを行キー中心で高スループット・低レイテンシに保存したい。|ワイドカラムNoSQLデータベース。
# 03 ネットワーク / 接続
Cloud NAT|外部IPを持たないVMからインターネットへ外向きIPv4通信したい。|マネージドNAT。外部からの新規接続は受け付けない。
Private Google Access|外部IPなしのVMから対応Google APIに到達できるようサブネットで設定したい。|対応Google APIへのアクセスを許可するサブネット設定。
VPC Network Peering|重複しないIP範囲の2つのVPC間でプライベート通信したい。|VPC間の経路交換。推移的なピアリングはできない。
Cloud VPN|オンプレミスとGoogle CloudのVPCをIPsecトンネルで接続したい。|暗号化されたサイト間VPNを提供する。
# 03 ネットワーク / 配信
Cloud Load Balancing|複数バックエンドへHTTP等のトラフィックを分散したい。|マネージドロードバランシングを提供する。
Cloud CDN|静的HTTPコンテンツをGoogleのエッジでキャッシュしたい。|対応ロードバランサーと組み合わせてコンテンツ配信を高速化する。
Cloud Armor|公開HTTPアプリに対するWAFルールで不審なリクエストを制御したい。|Webアプリ保護とDDoS防御の機能を提供する。
Cloud DNS|Google Cloudで管理するDNSゾーンを作成してレコードを管理したい。|マネージドDNSサービス。
# 04 運用 / 監視
Cloud Logging|アプリとインフラのログを集約して検索したい。|ログの収集、保管、検索、ルーティングを提供する。
Cloud Monitoring|CPU等のメトリクスの可視化とアラート通知を行いたい。|メトリクス、ダッシュボード、アラートを管理する。
Cloud Audit Logs|誰がプロジェクトの管理操作を行ったか監査したい。|監査ログに管理アクティビティ等を記録する。
Cloud Trace|サービスを横断するリクエストの処理時間を分散トレースで分析したい。|リクエストレイテンシの内訳をトレースする。
