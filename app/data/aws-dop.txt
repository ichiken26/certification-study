# 01 SDLC自動化 / デプロイ戦略
ブルーグリーンデプロイ|新旧2つの完全な環境を用意し、新環境に切り替えて問題時に旧環境へ戻せる方式は？|稼働環境と新環境を分離して切り替える。
カナリアデプロイ|新バージョンへまず少量の実トラフィックを流し、問題がないことを確認して移行したい。|限定的に新バージョンを公開して影響を小さくする。
ローリングデプロイ|既存のインスタンス群を小さな単位で順に更新し、全台同時停止を避けたい。|一部ずつ更新してサービス継続を目指す。
All-at-once|全トラフィックを一度に新バージョンへ切り替える方式は？|切替は短時間だが問題時の影響範囲が大きくなり得る。
# 02 構成管理 / IaC
CloudFormation Change Set|CloudFormationスタック更新前に変更されるリソースの内容を確認したい。|変更セットで更新予定内容や置換などを確認する。
CloudFormation Drift Detection|実際のリソース設定がテンプレートで定義された状態からずれていないか確認したい。|対応リソースの実設定と期待状態の差異を検出する。
CloudFormation StackSets|複数AWSアカウントとリージョンへ同じスタックを一元展開したい。|指定したアカウント・リージョンでスタックインスタンスを管理する。
CloudFormationロールバック|スタック更新が失敗した場合に以前の動作状態へ戻す標準機能は？|失敗時に変更を取り消す。リソースの状態によって手動対応が必要な場合もある。
# 03 監視・インシデント / 自動修復
EventBridgeルールとSystems Manager Automation|特定のAWSイベントを検知したら事前定義した運用修復手順を実行したい。|イベント駆動でAutomationランブックを開始する構成を作れる。
CloudWatchアラームとCodeDeployロールバック|デプロイ中にエラー率が悪化したら自動で旧バージョンへ戻したい。|CodeDeployにアラームと自動ロールバック設定を連携する。
AWS Configルールと修復アクション|組織のリソース構成が非準拠になったとき自動修復を実行したい。|ルールの非準拠判定をSSM Automation等の修復に接続できる。
CloudWatch Logs Insights|インシデント時に複数ロググループからエラー条件を検索・集計したい。|ログのクエリを使い障害の範囲を特定する。
# 04 セキュリティ / 配信
OIDCフェデレーション|GitHub Actionsから長期アクセスキーなしにAWSへデプロイしたい。|OIDCトークンをAWS STSで一時認証情報へ交換する。
CodeArtifact|組織内のnpm等のパッケージを管理するAWSのアーティファクトリポジトリは？|依存パッケージの保存・配布と上流リポジトリ接続を提供する。
ECRイメージスキャン|コンテナイメージの既知脆弱性をリリース前に検出したい。|ECRのスキャン機能等でパッケージの脆弱性を確認する。
Secrets Manager|CI/CDや実行環境から取得するDBパスワードを安全に管理したい。|シークレットの保管とアクセス制御を行う。
