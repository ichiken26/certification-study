# 01 データ取り込み・変換 / パイプライン
Kinesis Data Streams|大量のイベントをリアルタイム収集し、コンシューマーが保持期間中に再読できるようにしたい。|ストリームの保持とシャード等による処理を提供する。
Amazon Data Firehose|ストリームイベントを一定サイズや時間でバッファし、S3へ継続的に配送したい。|マネージドな配送を行い対応する変換処理も可能。
AWS Glue ETL|S3上の生データをSparkベースで変換してParquetへ出力したい。|マネージドETLジョブを実行する。
AWS DMS CDC|稼働中のソースDBで発生する変更を継続的にターゲットへ取り込みたい。|変更データキャプチャで差分を複製する。
# 02 ストレージ管理 / 分析
Athena|S3に保存済みのデータをサーバーレスSQLで分析したい。|データを別DBにロードせずSQL分析できる。
Redshift|列指向のデータウェアハウスへ多数のテーブルをロードして複雑なBI集計を行いたい。|分析SQLに最適化されたデータウェアハウス。
Glue Data Catalog|AthenaやETLから共用するテーブルのスキーマとパーティションのメタデータを管理したい。|データセットのメタデータを保存する。
Lake Formation|データレイクの表・列等へのきめ細かい権限を統合管理したい。|対応サービスと統合してデータレイクのアクセス権を制御する。
# 02 ストレージ管理 / データ形式
Parquet|列単位の選択・圧縮に適した列指向ファイル形式で、分析クエリのスキャンを減らしたい。|列指向のバイナリ形式。必要な列を読み出しやすい。
CSV|単純な区切りテキストとして表をやり取りする形式は？|人間が読みやすいが型や列指向圧縮等の機能は限定される。
JSON Lines|各行を独立したJSON値として保存し、イベントログを行単位で処理したい。|各レコードをJSONとして行単位に記録する。
Avro|スキーマに基づく行指向のバイナリ形式で、イベントのシリアライズに用いたい。|スキーマとシリアライズを用いたレコード指向形式。
# 03 運用・品質 / 最適化
パーティションプルーニング|日付で分割したS3データをAthenaで特定日のみ読み、不要ファイルの読み取りを省きたい。|パーティション条件で対象パスを絞りスキャンを減らす。
Glueジョブブックマーク|対応するGlue ETLジョブで前回処理済みのデータを追跡し、増分処理したい。|処理状態を記録して再処理を抑える。
Glue Data Quality|ETLの中でNULLの割合や行数等のデータ品質ルールを評価したい。|データ品質のルール評価と結果の監視を支援する。
Redshift Spectrum|RedshiftからS3上の外部テーブルを直接SQLで参照したい。|外部データをRedshiftのクエリに統合する。
