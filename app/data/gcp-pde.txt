# 01 データ処理設計 / サービス
Dataflow|Apache Beamのパイプラインでバッチとストリーミング処理をマネージド実行したい。|分散データ処理パイプラインを実行する。
Dataproc|既存Spark/HadoopのジョブやエコシステムをGoogle Cloud上で利用したい。|マネージドSpark/Hadoop環境を提供する。
Cloud Composer|Apache AirflowのDAGで複数データ処理の依存関係を管理したい。|マネージドAirflowでワークフローをスケジュールする。
Datastream|対応DBの変更をCDCで継続取得し、BigQuery等へ複製したい。|マネージド変更データキャプチャ・複製を提供する。
# 02 データ格納 / DB
BigQuery|大規模データの列指向SQL分析をマネージドデータウェアハウスで行いたい。|OLAP向けの分析サービス。
Bigtable|大量の時系列データを行キーによる低レイテンシ読み書きで処理したい。|ワイドカラム型NoSQLデータベース。
Spanner|グローバルな強整合性トランザクションと水平スケーリングが必要。|分散リレーショナルデータベース。
Cloud Storage|データレイクの生ファイルをオブジェクトとして低頻度アクセス階層も使い分けたい。|オブジェクトストレージ。ストレージクラス等を管理する。
# 03 BigQuery最適化 / SQL
日付パーティショニング|日付範囲で検索する巨大BigQueryテーブルで、対象日付以外の読み取りを避けたい。|パーティション条件でスキャン対象を絞る。
クラスタリング|BigQueryのパーティション内で顧客IDなど頻繁にフィルタする列によりブロックを整理したい。|クラスタ列によってブロックプルーニングが期待できる。
マテリアライズドビュー|頻繁に実行する対応集計クエリの結果を事前計算し、再計算を減らしたい。|対応条件のクエリ結果を維持して分析性能を向上する。
最大課金バイト数 (maximum bytes billed)|オンデマンドBigQueryクエリが許容するスキャン課金量を超える場合、実行を防ぎたい。|クエリの上限を設定する。ドライランで事前見積もりも可能。
# 04 セキュリティ・品質 / データ管理
行レベルアクセスポリシー|BigQueryの同じテーブルを使いながら利用者に許された行だけ参照させたい。|行フィルターをアクセスポリシーとして定義する。
列レベルアクセス制御|BigQueryの機密列にだけ追加のアクセス権を要求したい。|ポリシータグ等で列への参照権限を制御する。
Authorized View|利用者に元テーブルの直接アクセスを許さず、必要な列・行だけをビュー経由で提供したい。|承認済みビューに元データへのアクセスを付与する。
VPC Service Controls|対応Google Cloudサービスを通じた機密データの境界外への持ち出しを制限したい。|サービス境界でAPIアクセスとデータ移動を制約する。
