# 01 設計 / データ基盤
Pub/SubとDataflowとBigQuery|大量のイベントを受信してストリーム変換し、SQL分析したい。サーバーは管理しない。|Pub/Subで受信を疎結合化しDataflowで変換、BigQueryで分析する。
Cloud RunとCloud SQL HA|変動の大きいWeb APIと既存PostgreSQLを運用し、AZ障害へのDB切替を備えたい。|Cloud Runでコンテナを実行しCloud SQLの高可用性構成でDBを冗長化する。
Cloud StorageとCloud CDN|世界に静的メディアを配信し、キャッシュにより配信遅延とオリジン負荷を抑えたい。|オブジェクト保存とエッジキャッシュを組み合わせる。
Spannerのマルチリージョン構成|世界規模の取引システムに強い整合性と複数リージョンへの冗長性が必要。|分散リレーショナルDBとして強整合性と複数リージョン構成を提供する。
# 02 セキュリティ / 組織設計
Shared VPC|ネットワーク管理チームがホストプロジェクトでVPCを管理し、複数サービスプロジェクトがサブネットを共有したい。|ネットワーク管理とワークロード管理を分離できる。
VPC Service Controls|BigQueryやCloud Storage等の対応APIでサービス境界を設け、データ持ち出しリスクを低減したい。|サービス境界によりAPIを通じたアクセスやデータ移動を制約する。
Identity-Aware Proxy|公開WebアプリにVPNを要求せず、利用者のGoogle IDとIAM権限に基づくアクセス制御を前段に置きたい。|IAPが認証・認可を行い対象アプリへのアクセスを制御する。
Cloud KMS CMEK|対応マネージドサービスの保存時暗号化鍵を顧客管理キーとして権限やローテーションを管理したい。|CMEKでCloud KMSの鍵を指定する。対応状況はサービスごとに異なる。
# 03 運用・可用性 / 指標
SLI|成功リクエスト割合などサービスの実際の品質を計測する指標は？|Service Level Indicator。測定可能なサービス品質指標。
SLO|成功率99.9%など、SLIの達成目標を定めるものは？|Service Level Objective。サービス品質目標。
SLA|サービス品質を契約上の保証や補償条件として定義するものは？|Service Level Agreement。契約上の合意。
エラーバジェット|SLOに基づいて許容できる障害や失敗の量を表す概念は？|目標と完全成功との差分を用いて信頼性と変更速度を調整する。
# 03 運用・可用性 / DR
リージョンMIG|VMを複数ゾーンで自動管理し単一ゾーン障害に備えるCompute Engine構成は？|Managed Instance Groupをリージョン単位で構成する。
Cloud SQLのクロスリージョン読み取りレプリカ|別リージョンでDBの読み取りを行い、必要時にレプリカ昇格によるDRを検討したい。|別リージョンに非同期レプリカを作る。昇格手順やデータ損失を考慮する。
グローバル外部Application Load Balancer|複数リージョンのHTTPバックエンドに1つのグローバルな外部入口からアクセスさせたい。|ヘルスチェックとグローバルな負荷分散で正常なバックエンドへ誘導する。
Cloud Storageデュアルリージョン|特定の2リージョンにオブジェクトデータを冗長化したい。|指定したリージョンの組み合わせでデータ冗長化を行う。
