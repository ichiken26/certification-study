# 01 モニタリング・復旧 / 性能調査
EC2のStatusCheckFailed_System|EC2の基盤ネットワークや物理ホストの障害をゲストOSの異常と区別したい。|SystemステータスチェックはAWS基盤側の問題を検出する。|StatusCheckFailed_Instance|ゲストOS等のインスタンス側の問題を検出する。|CPUUtilization|CPU使用率であり基盤障害を直接区別しない。|NetworkOut|送信バイト数を表す。

SSM Run CommandのMaxConcurrency|タグで対象指定した100台に設定変更を配布する。最大5台ずつ実行して影響を抑えたい。|MaxConcurrencyを5に設定し、同時に実行する対象の数を制限する。|MaxErrorsを5に設定|エラー許容数の制御で並行実行数ではない。|コマンドの出力先をS3に設定|実行結果の保存先で並行度は変わらない。|SSM Agentのバージョンを変更|対象数の制御を指定していない。
SSM Run CommandのMaxErrors|100台へのコマンド配布で一定数のエラー発生後、新しい対象への実行を停止したい。|MaxErrorsは許容するエラー件数・割合の設定で、閾値超過後の新規実行を抑える。実行中のものは完了しうる。|MaxConcurrencyのみ|同時実行数を制限するが失敗件数による停止条件ではない。|コマンドタイムアウトだけ短縮|個別処理の時間制限でエラー総数による停止ではない。|実行結果をS3へ出力|失敗を記録できるが新規実行停止を設定しない。
SSM Inventory|管理対象EC2のインストール済みアプリケーションの一覧を継続的に収集したい。|Inventoryで管理対象ノードのソフトウェアや構成情報を収集できる。|CloudTrail管理イベント|AWS管理APIの監査ログでOS内の全ソフトウェア一覧ではない。|EBSスナップショット|ディスクデータのバックアップで一覧の収集・検索を提供しない。|Route 53ヘルスチェック|エンドポイントの正常性確認。
SSM Patch ManagerのScan操作|本番ノードに更新を適用せず、パッチベースラインに対して不足しているパッチを調べたい。|Scan操作はパッチ準拠状態を調査し、パッチのインストールは行わない。|Install操作|承認済みの不足パッチをインストールする。|SSM Agentをアンインストール|管理対象のパッチ状態を取得できなくなる。|EC2を再起動するだけ|パッチベースラインに基づくスキャンを行わない。
SSM Distributor|社内製の監視エージェントをパッケージとして多数の管理対象ノードに配布し、バージョンを管理したい。|Distributorはソフトウェアパッケージの作成・配布やバージョン管理を支援する。|SSM Parameter Store|設定値を保存するがパッケージ配布そのものではない。|CloudWatchアラーム|メトリクスの状態監視。|AWS Health Dashboard|AWSのサービスイベント情報を確認する。
